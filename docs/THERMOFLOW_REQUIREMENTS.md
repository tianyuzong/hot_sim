# ThermoFlow 智能工程仿真平台需求说明

> 文档状态：需求草案，待评审  
> 更新日期：2026-09-05  
> 当前重点：从“上传 STL 后执行一次热求解”升级为“由自然语言 Agent 辅助建模、由用户确认参数、由确定性求解器计算、在三维画布中展示真实结果”的通用工程仿真平台。

## 1. 产品定义

ThermoFlow 面向缺少完整仿真建模经验、但了解工件用途和工作环境的用户。

用户可以上传一个只有几何信息的 STL 文件，用自然语言描述工件的用途、材料、工作环境和需要验证的问题。系统中的 GPT Agent 将对这些信息进行理解和结构化，识别缺失条件并向用户追问，生成可编辑的仿真方案。用户确认后，本地确定性程序完成几何处理、网格划分和数值求解，并将真实的温度、热流、应力、形变等结果映射到三维模型上，最终给出有依据、可追溯的工程评估。

平台需要兼容尺度、结构和应用差异很大的工件，例如：

- 微米至毫米尺度的芯片封装、散热器和电子器件；
- 毫米至米尺度的机械零件、模具、壳体和管路；
- 高温、高压、强热流条件下的航空航天发动机及其部件；
- 单材料零件、多材料组件及包含接触面的装配体。

## 2. 核心目标

1. 将“几何文件 + 用户自然语言描述”转换为明确、完整、可验证的仿真输入。
2. 允许用户对 STL 中每个组件或区域单独指定材料和物理属性。
3. 让自然语言输入和结构化表单双向同步，且以用户确认后的结构化数据为求解依据。
4. 由真实数值求解器完成仿真，GPT 不生成或伪造数值场。
5. 在三维画布上展示真实网格和求解场，而不只提供格式化文字结果。
6. 将结果解释为用户能理解、能定位、能采取行动的工程结论。
7. 对假设、数据来源、模型能力、误差和不确定性保持透明。
8. 前端保持专业、清晰、可操作，默认不展示内部日志、JSON、调用链和机器执行过程。

## 3. 基本原则与边界

### 3.1 STL 的含义

STL 通常只包含三角面片几何，不包含以下信息：

- 真实单位和绝对尺寸；
- 材料及其物理属性；
- 零件名称和功能语义；
- 热源、载荷、约束和边界条件；
- 接触关系、接触热阻或连接方式；
- 允许温度、强度、寿命等工程判据。

因此，系统不能在仅有 STL 的情况下直接声称工件“可以稳定工作”。必须先补齐材料、工况、边界条件、持续时间和评估标准。

### 3.2 各模块职责

| 模块 | 主要职责 | 不应承担的职责 |
| --- | --- | --- |
| GPT Agent | 理解自然语言、结合上下文、识别意图、追问缺失参数、生成结构化仿真草案、解释结果、编排可用工具 | 凭空生成材料参数、伪造求解结果、绕过用户确认、替代有限元/有限体积求解器 |
| 几何与网格模块 | 解析、校验、修复、分区、网格划分、质量检查 | 猜测材料和工况 |
| 材料系统 | 提供有来源、有单位、有适用温度范围的物性数据 | 接受无来源的 Agent 臆测值作为权威数据 |
| 数值求解器 | 根据已确认模型执行确定性求解，输出场数据、收敛和守恒信息 | 根据自然语言自行改变建模条件 |
| 结构化界面 | 展示并编辑最终输入，是用户确认后的事实来源 | 默认暴露内部实现、原始日志或 GPT 工具轨迹 |
| 三维画布 | 展示真实几何、网格、边界条件和结果场，并支持空间定位与分析 | 用装饰性渐变假装仿真结果 |

### 3.3 数据优先级

发生冲突时按以下顺序处理：

1. 用户在结构化界面中确认的值；
2. 用户明确输入并经系统校验的自然语言条件；
3. 材料数据库中有版本和来源的数据；
4. 系统默认值或 Agent 建议值。

默认值和 Agent 建议必须被标记为“待确认”，不能静默进入正式求解。

## 4. 目标用户流程

```text
创建项目
  -> 导入 STL
  -> 确认单位与实际尺寸
  -> 几何校验、修复和组件/区域识别
  -> 用户描述用途、环境和希望验证的问题
  -> GPT Agent 解析为结构化仿真草案
  -> Agent 对缺失或矛盾信息进行追问
  -> 用户在组件、材料、工况、边界和判据面板中检查并确认
  -> 生成并检查网格
  -> 执行确定性数值求解
  -> 在三维画布上查看真实结果场
  -> 查看关键指标、风险位置、可信度和工程评估
  -> 必要时修改条件重新求解
  -> 可选：启动 Agent 目标优化闭环
  -> 保存、比较并导出研究结果
```

### 4.1 普通仿真与 Agent 优化的关系

- **应用并求解**：将当前已确认的材料、工况和边界条件应用到模型，执行一次仿真。这是主流程。
- **查看结果**：打开本次研究的三维结果及指标，不应触发新的计算。
- **Agent 优化**：在已经有明确目标和可修改变量时，自动提出并执行多轮候选方案，比较结果并选择满足目标的研究。它是可选流程，不是完成普通仿真的前置条件。
- Agent 优化中的每一轮都必须对应一个可查看、可复现的独立研究，不能只留下文字日志。

## 5. 功能需求

### 5.1 项目与研究管理

- 一个项目保存几何、组件、材料、场景和全部研究历史。
- 一次“求解”产生一个不可混淆的研究版本，记录输入快照、求解器版本和结果。
- 支持复制研究、修改参数后重新运行。
- 支持并排比较两个或多个研究的场分布和关键指标。
- 用户界面使用可理解的名称和时间，不默认显示内部 UUID。
- 删除、覆盖或重算结果前需要明确提示其影响。

### 5.2 几何导入、校验与分区

导入 STL 后，系统至少需要完成：

- 检测二进制/ASCII STL、三角面数量、包围盒和几何尺度；
- 要求用户确认单位，并展示换算后的实际尺寸；
- 检查封闭性、非流形边、反向法线、自交、重复面、孔洞和退化三角形；
- 检测断开的壳体，并允许将其作为候选组件；
- 对可修复问题给出预览、影响说明和可撤销修复；
- 对薄壁、微小特征和尺度跨度过大的区域给出网格风险提示；
- 支持组件合并、拆分、重命名、隐藏、隔离和颜色标识；
- 支持用户在三维画布中选择面、体、壳或手工区域；
- 保存稳定的组件和区域标识，避免重新加载后材料或边界条件错绑。

仅凭单个 STL 无法可靠恢复原始 CAD 装配语义。对于复杂装配体，应规划 STEP 等保留实体、部件和装配信息的格式支持。

### 5.3 组件与材料

每个组件或用户定义区域必须能单独设置材料。材料面板至少包括：

#### 热学属性

- 密度；
- 比热容；
- 导热系数；
- 发射率；
- 随温度变化的属性曲线；
- 各向同性、正交各向异性或完整各向异性设置。

#### 力学属性

- 弹性模量、泊松比；
- 热膨胀系数；
- 屈服强度、极限强度；
- 塑性、蠕变、疲劳等适用模型与参数；
- 允许工作温度、熔点或分解温度；
- 随温度变化的力学属性。

#### 复合与界面属性

- 多层、涂层、复合材料和方向；
- 组件之间的接触类型；
- 接触热阻、接触导热系数；
- 绑定、滑移、摩擦等机械接触设置。

材料数据需要显示：

- 数据来源、版本和引用；
- 单位和适用温度范围；
- 是数据库值、用户输入值还是待确认建议值；
- 缺失项和外推风险；
- 用户覆盖数据库值的记录。

GPT 可以建议“可能使用某类高温合金”，但不能直接编造该合金的数值属性。没有可靠数据时必须要求用户选择数据库材料或输入数据。

### 5.4 工况、物理场与边界条件

系统需要将用户描述转换为明确的仿真场景，包括：

- 工件用途和需要回答的工程问题；
- 环境温度、压力、介质、辐射环境；
- 初始温度和初始状态；
- 热源、体积发热、表面热流或功率分布；
- 对流换热系数和流体温度；
- 辐射边界及环境辐射温度；
- 固定温度、绝热、对称等边界；
- 压力、力、加速度、旋转和机械约束；
- 稳态或瞬态、工作持续时间和载荷时序；
- 组件间热接触与机械接触；
- 需要满足的最高温度、最大形变、安全系数、寿命等判据。

所有边界条件都必须绑定到具体组件、面或区域，并在三维画布上可见。系统需要检测空选择、重复约束、冲突条件和明显不完整的约束。

### 5.5 自然语言 Agent

#### 输入

Agent 可接收：

- 当前对话历史；
- 用户对用途、环境、材料、载荷和目标的描述；
- 本地程序提取的紧凑几何元数据；
- 组件、区域和材料候选列表；
- 当前结构化仿真草案；
- 平台当前支持的物理模型和求解能力。

默认不将大型原始 STL、完整网格或完整结果场直接发送给 GPT。应先由本地程序提取尺寸、壳体、组件、表面积、体积、薄壁特征等结构化摘要。

#### 输出

GPT 必须输出固定模式的结构化数据，而不是依靠 Markdown 文本或从自由文本中截取 JSON。结构至少包含：

- 用户意图和工程问题；
- 建议使用的物理场和分析类型；
- 组件与材料映射草案；
- 工况和边界条件草案；
- 评估目标和可修改变量；
- 明确假设；
- 缺失信息和需要追问的问题；
- 不支持或不确定的部分。

服务端必须再次验证：

- Schema 完整性；
- 单位、数值范围和量纲；
- 组件、区域和材料 ID 是否存在；
- 参数是否在材料适用范围内；
- 所选物理模型是否受当前求解器支持；
- 必填信息是否齐全；
- Agent 建议是否需要用户确认。

#### 对话行为

- 一次只追问最关键、最影响建模正确性的问题组。
- 将自然语言中的值立即映射到右侧结构化字段并高亮待确认改动。
- 当用户在表单中修改值时，Agent 获取更新后的结构化上下文。
- 对模糊表达给出单位和含义澄清，例如“很热”不能直接转换为确定温度。
- 解释为什么需要某个参数，以及缺少它会影响哪个结论。
- 不展示内部推理、工具调用轨迹、原始模型响应或请求报文。

#### GPT 接入安全

- ThermoFlow 部署在哪台服务器，就由该服务器后端保存并使用自己的 GPT API 密钥。
- yihongzhu 服务器可以通过服务端环境变量或密钥管理设施独立配置密钥，并由 ThermoFlow 后端直接调用 GPT API。
- 不同部署实例可以分别配置、轮换和撤销各自的密钥，密钥不得写入项目源码或随部署包复制。
- 密钥不得出现在浏览器代码、接口响应、日志、报告或仓库中。
- 服务端负责请求构造、超时、重试、限流和错误降级。
- 保存用户确认后的结构化数据；原始对话的保存策略需要可配置。
- 对发送给外部模型的数据做最小化处理，并明确数据使用边界。

### 5.6 网格与求解

- 根据几何尺度、薄壁、小特征和目标物理场生成网格。
- 在求解前展示网格，并提供局部加密、整体尺寸和质量阈值设置。
- 显示网格单元数量、最差质量、风险区域和预计资源消耗。
- 不满足最低质量要求时阻止求解或要求用户明确确认风险。
- 支持取消、超时、失败恢复和资源不足提示。
- 保存求解器类型、版本、参数、收敛历史和守恒检查，供审计和高级诊断使用。
- 前端默认只展示阶段、进度、耗时和可操作状态，不滚动输出 solver stdout。

首期应明确支持边界，例如先实现：

1. 稳态导热；
2. 瞬态导热；
3. 对流和辐射边界；
4. 温度场驱动的热应力与形变。

发动机等复杂场景可能还需要共轭传热、燃烧、流体、非线性接触、塑性、蠕变和疲劳。若平台尚不支持，必须明确提示，不能用简化热传导结果代替完整“可稳定工作”结论。

### 5.7 三维工程可视化

可视化是主工作区，不是结果页中的装饰图片。

#### 建模阶段

画布需要支持：

- 真实 STL 几何显示、旋转、平移、缩放和标准视角；
- 组件树与画布选择双向联动；
- 隐藏、隔离、透明和分解视图；
- 面、组件、壳体和区域的拾取；
- 材料颜色或纹理图例；
- 边界条件、热源、载荷、约束和接触面的工程符号；
- 几何缺陷定位和修复前后对比；
- 表面网格/体网格切换及网格质量着色；
- 截面与裁剪工具，用于检查内部结构。

#### 结果阶段

画布必须直接读取求解器输出的网格节点/单元场，例如 VTK 系列数据，不得用人工渐变、模糊贴图或随机动画代替真实结果。

根据实际求解物理场，至少支持：

- 温度云图；
- 热流密度大小和矢量；
- 位移与形变，可切换真实比例和放大比例；
- 应力、应变和安全系数云图；
- 最小值、最大值及其空间位置；
- 鼠标探针、固定探针和组件统计；
- 截面、等值面、路径曲线和局部区域统计；
- 瞬态结果的时间轴、播放和指定时刻对比；
- 两个研究之间的结果并排或差值比较；
- 材料允许值叠加和超限区域高亮；
- PNG、场数据和结果报告导出。

颜色图例必须包含物理量、单位、最小值、最大值和当前时间。比较研究时可锁定相同色标范围，避免因自动缩放造成误判。稳态结果不得使用暗示时间变化的循环动画。

#### 结论与画布联动

- 点击“最高温度位于喷管喉部”等结论时，画布自动切换到对应结果场并聚焦该位置。
- 点击组件或超限区域时，右侧显示该位置的材料、边界、数值和允许值。
- Agent 引用某个结果时必须附带可定位的研究、物理量、组件/区域和时间步。
- “查看结果”必须切换到对应研究的结果模式并实际渲染场数据，不能只有文字或无响应。

### 5.8 结果解释与工程评估

结果页按以下顺序组织：

1. 三维结果画布；
2. 关键指标及其位置；
3. 是否满足用户明确设置的判据；
4. 风险组件和超限区域；
5. 假设、模型范围和不确定性；
6. 建议的下一步操作；
7. 可选的详细报告与高级诊断。

系统必须严格区分以下状态：

| 状态 | 含义 |
| --- | --- |
| 待补充信息 | 材料、工况、边界或判据不足，不能可靠求解或评估 |
| 已准备求解 | 必填条件已确认，模型检查通过 |
| 求解中 | 数值求解正在执行 |
| 求解完成 | 已产生可读取的数值结果，不代表满足工程目标 |
| 求解失败 | 求解器报错、发散、资源不足或结果文件无效 |
| 满足设定目标 | 本次研究满足用户明确输入的全部可判定标准 |
| 不满足设定目标 | 至少一个明确标准被违反，并给出位置和裕量 |
| 无法判定 | 虽有数值结果，但缺少材料限值、持续时间、评估标准或必要物理模型 |

禁止使用“计算通过”“可以采用”“可稳定工作”等含义模糊或证据不足的表述。稳定性结论至少需要明确材料、工况、持续时间、失效模式、允许限值、安全裕量和模型不确定性。

### 5.9 Agent 目标优化闭环

仅当用户已经定义以下内容时才允许启动：

- 可计算的目标，例如最高温度低于 900 K；
- 可修改变量，例如材料、壁厚、冷却温度或热流；
- 每个变量的合法范围、离散候选或约束；
- 最大轮数、资源预算和停止条件。

每轮优化应包含：

1. Agent 基于已有结果提出结构化变更；
2. 服务端验证变更是否合法；
3. 用户授权范围外的变更需要再次确认；
4. 求解器生成一个新的研究；
5. 系统比较指标、约束和不确定性；
6. 最终采用的研究可以直接在画布中打开并与基准研究比较。

界面展示“本轮修改了什么、指标如何变化、为什么停止”。内部执行步骤、工具调用、UUID 和原始日志不应成为主要内容。

## 6. 前端信息架构与界面规范

### 6.1 建议工作台布局

```text
+----------------+--------------------------------+----------------------+
| 项目/组件树    |                                | 结构化属性面板       |
|                |          三维工程画布          | 材料/条件/结果       |
| 几何与研究列表 |                                |                      |
+----------------+--------------------------------+----------------------+
| 状态与任务区 / 可折叠 Agent 对话区 / 可选高级诊断                  |
+------------------------------------------------------------------------+
```

主导航建议围绕任务组织：

- **几何**：单位、组件、缺陷和区域；
- **材料**：组件材料、物性和接触；
- **工况**：环境、载荷、边界和时序；
- **网格**：网格设置、质量和预览；
- **求解**：求解配置、进度和状态；
- **结果**：真实三维场、图表、探针和比较；
- **评估**：判据、风险、裕量和报告；
- **Agent 优化**：可选的目标驱动多轮优化。

Agent 对话应作为可折叠侧栏或底部抽屉与当前工作台共存，不应迫使用户在聊天页和模型页之间来回切换。

### 6.2 展示原则

- 页面优先展示用户当前需要做的操作，而不是系统内部过程。
- 每个字段显示名称、当前值、单位、来源、确认状态和必要的校验反馈。
- 组件树、属性面板、Agent 引用和三维对象始终保持联动。
- 使用明确的按钮文字，例如“生成网格”“开始求解”“查看结果”“比较研究”。
- 正常状态保持安静；警告说明影响，错误给出可执行的修复建议。
- 关键数值必须带单位，重要结论必须能追溯到研究和空间位置。
- 删除、覆盖、应用 Agent 建议等高影响操作需要确认和撤销能力。
- 长任务可以后台运行，但必须显示阶段、百分比或不确定进度、已用时间和取消入口。
- 在桌面和常用笔记本分辨率下，画布仍应保持足够可视面积；面板可折叠或调整宽度。

### 6.3 默认禁止展示的内容

普通用户界面不得直接展示：

- solver stdout/stderr；
- CUDA、驱动和设备初始化输出；
- GPT 原始响应、Token 信息和工具调用轨迹；
- 原始 JSON、HTTP 请求/响应和状态码；
- Python 堆栈、内部异常栈和文件系统路径；
- 数据库主键、研究 UUID 和临时文件名；
- “01/02/03/04”式机器执行步骤；
- 大段时间戳日志或内部调试信息。

用户真正需要看到的是：

- 当前状态；
- 对用户结果的影响；
- 失败或风险的可理解原因；
- 可以采取的下一步；
- 真实可视化结果和关键工程指标；
- 结果可信度、假设和适用范围。

### 6.4 高级诊断

技术日志仍需在服务端结构化保存，用于排障和审计，但只能通过明确的“高级诊断”入口访问，并进行脱敏和分级：

- 默认折叠，不占据主工作流；
- 隐藏 API 密钥、身份凭证和敏感路径；
- 提供可下载的诊断包，而非在页面无限滚动；
- 将用户可处理的问题与仅供运维使用的信息分开；
- 为每次任务提供短的可搜索诊断编号，必要时再映射到内部 ID。

## 7. 跨尺度和跨行业适配

平台不能假定所有 STL 都使用同一单位、网格策略或物理模型。

### 7.1 芯片与电子封装

可能需要：

- 微米/毫米单位和极薄层处理；
- 多层材料和各向异性导热；
- 芯片体积发热或功率分布；
- 界面材料和接触热阻；
- 封装、PCB、散热器和环境对流；
- 结温、热阻和热点位置评估。

### 7.2 常规机械工件

可能需要：

- 稳态/瞬态导热；
- 热源、对流、辐射和热接触；
- 热膨胀、约束应力和安全系数；
- 焊缝、连接、涂层和局部材料区域。

### 7.3 航空航天发动机

可能需要：

- 强热流、高温气体、辐射和内部冷却；
- 瞬态启停循环和空间变化边界；
- 温度相关材料、涂层和复合结构；
- 压力、离心载荷和热机械耦合；
- 塑性、蠕变、低周疲劳和寿命模型；
- CFD 或共轭传热提供的壁面条件。

若当前版本只能完成其中一部分，结果必须标记为“简化模型”，并列出未考虑效应及其可能影响。

## 8. 建议的结构化仿真规格

系统应维护一份版本化的 `SimulationSpec`，作为 Agent、表单、求解器和报告之间的共同契约。概念结构如下：

```yaml
project:
  name: string
geometry:
  asset_id: string
  unit: mm | m | um
  components:
    - id: stable-component-id
      name: string
      region_refs: []
materials:
  assignments:
    - component_id: stable-component-id
      material_id: database-or-user-material-id
      overrides: {}
physics:
  analyses: [steady_thermal, transient_thermal, thermo_mechanical]
scenario:
  purpose: string
  environment: {}
  duration: optional-time
conditions:
  initial: []
  thermal: []
  mechanical: []
  contacts: []
mesh:
  global_size: quantity
  local_refinements: []
solver:
  type: string
  tolerances: {}
criteria:
  - metric: max_temperature
    operator: less_than
    value: 900 K
assumptions: []
missing_information: []
confirmation:
  status: draft | needs_input | confirmed
  confirmed_by: optional-user
  confirmed_at: optional-time
```

所有物理量应使用“数值 + 单位”的结构存储，不能只保存无量纲裸数。各模块通过稳定 ID 引用组件和区域，显示层再转换为用户可读名称。

## 9. 非功能需求

### 9.1 正确性与可追溯性

- 每个结果必须能回溯到输入规格、几何版本、材料版本、网格和求解器版本。
- 修改任何会影响结果的输入后，应明确标记现有结果已过期。
- 需要记录收敛、守恒、网格质量和必要的验证信息。
- 报告必须区分输入事实、系统默认、Agent 建议和工程假设。

### 9.2 性能与稳定性

- 大型 STL 需要流式上传、后台处理和可取消任务。
- 三维画布需对大网格采用分层细节、抽样或服务端派生表示，但探针和数值查询仍基于真实结果。
- 浏览器刷新后可恢复当前项目、任务状态和结果视图。
- 求解服务异常不能导致项目输入丢失。

### 9.3 安全

- API 密钥、服务凭据和内部路径不得发送到前端。
- 上传文件需要类型、大小和恶意内容检查。
- 项目和结果需要访问控制与隔离。
- 日志、导出和错误信息必须脱敏。

### 9.4 可扩展性

- 几何、材料、求解器、结果字段和 Agent 工具采用明确接口。
- 新增物理场时不应破坏现有 `SimulationSpec`，需要 Schema 版本迁移。
- 支持后续接入 STEP、外部材料库、CFD、远程求解资源和优化算法。

## 10. 首期验收标准

以下条件同时满足，才可认为首个可用版本完成：

1. 用户可上传 STL、确认单位，并看到正确尺度的真实三维模型。
2. 系统能识别断开壳体作为候选组件，用户可调整组件/区域。
3. 每个组件都能在结构化面板中选择材料并查看/编辑必要物性。
4. 用户可用自然语言描述工况，GPT 返回受 Schema 约束的草案和缺失问题。
5. Agent 草案不会直接求解；用户可以在表单中检查、修改并确认。
6. 边界条件可绑定到三维面或组件，并在画布上可见。
7. 系统能生成并预览网格，显示基本网格质量。
8. 至少能可靠执行稳态和瞬态热求解，并保存可复现研究。
9. 结果页在三维画布上展示真实温度场和热流结果，支持图例、探针、极值定位和截面。
10. 若启用热机械分析，可展示真实应力和形变场并明确模型范围。
11. 结果摘要使用清晰状态，不再把“求解完成”写成“满足目标”。
12. 没有材料限值或判据时，系统显示“无法判定”，不声称稳定工作。
13. 点击任何 Agent 结论或“查看结果”，都会打开对应研究和对应三维场。
14. 默认前端不存在原始日志、JSON、内部路径、UUID 或机器执行步骤。
15. 高级诊断经过脱敏、默认折叠，并与普通工作流隔离。

## 11. 建议实施阶段

### 阶段 1：统一数据模型与界面骨架

- 建立版本化 `SimulationSpec`；
- 建立组件、区域、材料、条件、判据和研究的数据模型；
- 重构为组件树 + 三维画布 + 属性面板 + Agent 抽屉；
- 统一状态术语，移除主界面的原始日志和内部 ID。

### 阶段 2：几何、组件和材料建模

- STL 尺度确认和几何诊断；
- 断开壳体识别、手工区域选择和稳定 ID；
- 材料数据库、用户材料、温度相关属性和数据来源；
- 组件材料与接触设置。

### 阶段 3：GPT 结构化解析

- 服务端接入 GPT；
- 定义严格结构化输出 Schema；
- 实现上下文压缩、缺失信息追问和服务端校验；
- 实现对话与属性面板双向联动及用户确认流程。

### 阶段 4：真实网格与热仿真可视化

- 网格生成、质量检查和画布预览；
- 稳态/瞬态热求解；
- VTK 等真实场数据输出；
- 温度、热流、探针、截面、时间轴和极值定位。

### 阶段 5：热机械与工程评估

- 热应力、应变和形变；
- 材料允许值、超限区域和安全裕量；
- 假设、不确定性和模型适用范围；
- 研究比较和正式报告。

### 阶段 6：Agent 优化与高级能力

- 受约束的多轮方案优化；
- 候选研究自动比较和画布联动；
- STEP/装配体、复杂接触、外部 CFD 条件和更高级物理模型。

## 12. 待确认的产品决策

以下问题需要在进入完整开发前确定：

1. 首期正式支持范围是否为“稳态热 + 瞬态热 + 线性热机械”，还是只先完成热分析。
2. 首期材料数据库的来源、授权、覆盖材料种类和版本管理方式。
3. STL 多组件识别以断开壳体为主，还是首期就需要画布中的复杂手工分区。
4. 首期最大模型规模、单次求解资源上限和可接受等待时间。
5. 是否在首期支持 STEP；若不支持，复杂装配体如何向用户说明限制。
6. GPT 使用的具体模型、结构化输出接口、数据保留政策和费用上限。
7. 热机械、蠕变、疲劳、CFD 和共轭传热分别进入哪个版本。
8. 用户可否允许 Agent 在预先授权的范围内自动连续求解，还是每一轮都需要确认。

---

本需求的核心不是让 Agent “看一眼 STL 就判断能不能用”，而是让 Agent 帮助用户把模糊的工程描述逐步变成可信的仿真模型；由用户确认事实，由材料数据提供物理依据，由数值求解器产生真实结果，再通过三维画布和清晰的工程语言解释这些结果。
