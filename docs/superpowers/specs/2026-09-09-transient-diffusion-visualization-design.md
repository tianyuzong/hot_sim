# 瞬态热扩散可视化与自适应时间采样设计

日期：2026-09-09

## 1. 背景与问题

当前 60 秒演示算例使用 `20 × 10 × 5 mm` 的 C110 紫铜工件、4 个总功率 `70 W` 的热源、`1 s` 时间步长和绝热外表面。铜的热扩散率约为 `1.136 × 10⁻⁴ m²/s`，1 秒扩散长度约为 `10.66 mm`。因此第一帧出现时，热量已经扩散到大部分工件。

真实结果并非完全等温：`1 s` 时最低温度为 `311.49 K`，最高温度为 `319.05 K`，热点位于主热源映射位置附近。但是该帧 `7.56 K` 的空间温差只占当前固定绝对温标 `293.15–1519.15 K` 的约 `0.62%`，导致工件看起来几乎是单一颜色。

当前算例还存在两个物理解释风险：4 个热源分散覆盖 23 个体素，削弱了单点传播特征；外表面没有散热条件，70 W 全部转化为蓄热，使工件平均温度约以 `20.34 K/s` 上升。最终温度 `1519.15 K` 已远超演示材料数据的有效上限 `473.15 K`。

## 2. 目标

1. 在不伪造、不插值温度结果的前提下，清楚显示“热源附近先升温、热量再向周围扩散”。
2. 播放过程中所有色标数字保持固定。
3. 保留绝对温度视图，避免相对温差图被误认为绝对温度。
4. 对高导热材料自动保存足够密集的早期真实时间帧，同时覆盖用户指定的完整仿真时长。
5. 当结果超出材料物性有效温区时明确告警，避免把常物性外推结果当作可靠工程结论。
6. 继续沿用一次预载全部温度帧、浏览器本地顺滑播放的现有机制。

## 3. 非目标

- 不实现热源沿轨迹连续移动；一次求解内热源位置仍然固定。
- 不用前端动画或空间插值制造求解器没有计算的中间温度场。
- 不自动添加用户未指定的对流、定温或辐射边界。
- 不在本次修改中改变热流、剖面和算例差值视图的数据加载策略。
- 不引入温度相关材料模型或相变模型；超温时只告警并说明限制。

## 4. 用户界面行为

### 4.1 两种温度视图

瞬态结果提供两个明确区分的按钮：

- `热扩散`：瞬态结果默认视图。每个顶点显示 `T(x,t) - Tmin(t)`，即相对当前帧最低温度的空间温差。
- `绝对温度`：显示真实绝对温度 `T(x,t)`，延续现有全时段固定绝对温标。

稳态结果不显示 `热扩散` 按钮，继续使用绝对温度视图。

### 4.2 热扩散色标

加载完全部帧后，前端一次计算：

`ΔTspace,max = max_t(max_x(T(x,t)) - min_x(T(x,t)))`

播放任意帧时，热扩散色标固定为：

- 低端：`0 K`
- 中点：`ΔTspace,max / 2`
- 高端：`ΔTspace,max`

标题显示 `空间温差 ΔT = T − 本帧最低温度 · 全时段固定`。标题中的当前时间可以变化，三个色标数字不得变化。

当前帧绝对最低、最高温度仍显示在结果详情中，标签必须保留 `当前帧` 字样。热扩散视图还显示当前帧参考温度 `Tmin(t)`，防止用户将相对色彩误读为绝对温度。

若整段结果的最大空间温差小于数值容差，工件使用单一中性色，并显示 `该结果在当前网格与容差下近似等温`，不能人为放大数值噪声。

### 4.3 默认选择

首次打开包含多个时间帧的结果时默认进入 `热扩散`。用户手动切换到 `绝对温度` 后，在该算例浏览期间保留选择。稳态、热流、等值带、剖面和差值视图保持原有行为。

## 5. 自适应真实时间帧

### 5.1 设计原则

用户输入的 `time_step_s` 改为数值积分的最大允许步长，而不是强制所有输出帧等间隔。求解器可以在热扩散初期使用更小的真实积分步长，后期逐渐放宽，但任何内部步长不得超过用户确认值。

### 5.2 早期时间尺度

使用网格尺寸和最快材料扩散率估算单元扩散时间：

- `αmax = max(k / (ρ cp))`
- `tcell = h² / αmax`
- `dtearly = min(time_step_s, 0.25 × tcell)`

其中 `h` 为实际体素间距。若材料参数无效或无法计算扩散率，则退回现有均匀时间网格，并记录退回原因。

### 5.3 输出时间表

一个瞬态结果最多保存 201 帧，包含 `t = 0` 和用户指定的最终时刻。默认生成 200 个输出区间：

1. 若 `dtearly` 不小于均匀输出间隔，则使用均匀输出时间。
2. 否则使用幂次时间表 `ti = duration × (i / N)^p`。
3. 指数 `p` 由首个正时间不大于 `dtearly` 的条件计算，并限制在 `[1, 4]`。
4. 相邻输出时刻之间如大于 `time_step_s`，求解器使用若干内部子步推进，只在输出时刻保存结果。
5. 最终输出时间必须精确等于用户确认的 `duration_s`，时间数组必须严格递增。

该时间表不会通过插值生成帧。每个输出帧都来自真实隐式热传导积分状态。

### 5.4 数值求解

后向欧拉离散继续使用现有导热矩阵、热容矩阵、边界项和 CPU/CUDA 后端。非均匀步长仅改变每一步中的 `C / Δt` 系数。能量平衡、边界功率和蓄热速率必须按该步实际 `Δt` 计算。

现有瞬态结果模型继续通过 `time_steps` 保存非均匀 `time_s`，无需增加第二套播放接口。现有 `/playback` 批量接口继续返回共享网格和全部真实温度数组。

## 6. 材料有效温区告警

求解完成后，结果页将整个时间段的最低/最高温度与每个组件材料的 `valid_temperature_min_k`、`valid_temperature_max_k` 比较。

超出时显示高可见度告警，内容包含：

- 组件和材料名称；
- 材料数据有效温区；
- 仿真结果温区；
- `当前求解使用常物性外推，未建模温度相关物性和相变，结果不可直接作为工程结论`。

告警不删除结果，也不阻止查看或下载数值文件。

## 7. 数据流与组件边界

1. 研究确认层继续保存持续时间和最大积分步长。
2. 网格完成后，求解器根据实际网格间距及组件材料计算输出时间表。
3. 瞬态积分器在每个真实输出时刻生成温度、热流、能量平衡和热点信息。
4. 结果仓储按非均匀 `time_s` 保存最多 201 个帧文件。
5. `/playback` 一次返回共享表面网格和全部真实温度帧。
6. 前端缓存绝对温度数组，并为热扩散视图派生每帧空间温差数组；派生操作只改变着色标量，不修改或覆盖原始温度。
7. Three.js 视口根据当前模式选择绝对温标或空间温差温标，两者都在整段播放期间固定。

## 8. 失败处理

- 自适应时间表计算失败：退回均匀时间表并在结果假设中记录原因。
- 非均匀积分某一步失败：任务失败并保留具体时刻、步长、计算后端和诊断码，不发布不完整结果。
- 播放包缺帧或网格不一致：禁止播放并提示重新求解，不用前端补帧。
- 空间温差数组长度与共享网格不一致：停止热扩散视图并保留绝对温度结果。
- 材料没有有效温区：显示 `材料有效温区未提供`，不虚构上下限。

## 9. 测试与验收

### 9.1 数值测试

- 时间表包含 0 和最终时刻、严格递增、输出不超过 201 帧。
- 高扩散率材料的首个正时间不大于 `0.25 h²/αmax`。
- 任意内部步长不超过用户确认的 `time_step_s`。
- 非均匀后向欧拉的一阶解析冷却算例收敛，能量闭合满足现有容差。
- 点热源算例的首批帧中，热源附近温升早于远端；热点位置与热源映射位置相符。
- CPU 和 CUDA 输出时间数组一致，结果在现有数值容差内一致。

### 9.2 API 测试

- 结果与播放接口保留非均匀 `time_s`，帧数和温度数组一致。
- 播放包仍只传一次共享网格，不为每帧重复顶点和三角面。
- 旧的均匀时间结果仍可读取和播放。

### 9.3 浏览器验收

- 瞬态结果默认显示 `热扩散`。
- 在 `0 s` 时工件为冷态；后续早期帧先在热源附近出现高温色，随后向周围扩展。
- 快速拖动时间轴不产生 `/frames/{index}` 或 `/view` 请求。
- 热扩散模式从第一帧到最后一帧的三个色标数字完全相同。
- 绝对温度模式从第一帧到最后一帧的三个色标数字完全相同。
- 两种模式切换不修改当前时间步，也不重新请求播放包。
- 当前 C110 铜演示结果显示材料有效温区超限告警。

## 10. 部署与兼容性

- 旧结果没有自适应早期帧，仍可在两种视图中播放；只有重新求解后才能获得更密集的早期真实场。
- 部署后为前端资源更新缓存版本，避免再次打开旧的 `file://` 或浏览器缓存页面。
- Firework 服务重启前检查无运行中的求解任务；重启后验证 CUDA 后端、批量播放接口和既有结果读取。
- 为验证“先热后扩散”，部署后从现有算例复制一个新研究并重新求解；不覆盖旧研究。

## 11. 完成标准

完成必须同时满足：

1. 新研究包含真实的早期密集帧并覆盖完整 60 秒。
2. 热扩散视图能清楚区分主热源附近与远端区域，且热点位置匹配数值结果。
3. 播放或拖动时色标数字不变化，只改变工件着色与当前帧绝对温度详情。
4. 绝对温度和空间温差的含义在界面上不混淆。
5. 超出材料有效温区时出现明确告警。
6. CPU/CUDA、API、浏览器和全量回归测试通过。
